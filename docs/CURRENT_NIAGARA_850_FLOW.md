# Current Niagara inbound 850 flow

1. `__main__.py` accepts one file, scans an app-owned inbox, or starts `dashboard.create_app`. Web uploads are saved in `manual/` or `previews/`; watcher files are read from the configured inbox. A direct AS2 file needs the matching verified `.as2.json` receipt; a configured controlled drop does not.
2. `service.process_file` hashes and registers the file in SQLite before parsing. `fixed850.parse_fixed_850` reads `EDI850Inbound` SOHEAD/SOLINE/SRHEAD/SRLINE/TOTALS and validates pairing, counts, customer, addresses, lines, and quantities. `edi.parse_850` handles the implemented X12 004010 850 subset with ISA/GS/ST/SE/GE/IEA validation.
3. The sender selects a JSON customer profile. Fixed-width files require matching company and plant. Direct X12 checks ISA IDs, transport profile, and AS2 receipt when configured. Item and unit cross references come from the profile or `CustItemRef` for fixed-width files. `AddressResolver` reads `PUB.PV_CustAddress` through the configured ODBC DSN; direct X12 can use an explicit address map.
4. `build_sales_order` creates a Radius REST payload. Historical requested/shipping dates are changed in memory to the current server date and recorded in file events. `SOrderDate` is omitted and `SOSourceCode` is `EDI`. The source file stays unchanged.
5. `RadiusClient.post` Base64 wraps JSON for `XLinkAPISOrder`, decodes the response, checks top-level and nested errors, and returns the acknowledged Sales Order. Only then does `build_shipping_request` use returned item codes and line numbers to create one or multiple `XLinkAPIShipReq` requests.
6. SQLite `orders` records idempotency state and SO/SR numbers; `radius_records` saves each confirmed POST/decoded response. `files` and `file_events` keep status and history. Success moves app-owned inbox files to `processed/`; failure goes to `failed/`; previews remain available for later submission. Uncertain partial POSTs require reconciliation.

The REST endpoint is `http://P-RAD-FSM-EF.fsm.corp:8081/radadapter/radius/api` in TEST by default. ODBC is used only for address lookup. There is no Radius flat-file publication or inbound XLink batch execution in this flow. Existing Sales Order/Shipping Request creation must remain intact. Update submissions are held while Radius price-group behavior is investigated.
